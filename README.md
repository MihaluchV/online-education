# Клас-код — платформа для практичних із програмування та веб-дизайну

Онлайн-платформа для спільної одночасної роботи класу над практичними завданнями з веб-дизайну (HTML, CSS, JavaScript) та програмування (Python). Учні пишуть код у браузері й одразу бачать результат, а вчитель у реальному часі бачить екрани всіх учнів, спілкується з ними в чаті, перевіряє роботи й веде журнал оцінок.

Це статичний сайт (сторінка `index.html` і поруч з нею файл стилів та кілька файлів скриптів, без папок), який працює на безкоштовному GitHub Pages. Окремого сервера немає: дані зберігає Firebase (Realtime Database + Authentication).

> Інтерфейс українською мовою.

---

## Можливості

### Для вчителя
- **Реєстрація та вхід** (ім’я, по батькові, прізвище, пошта, логін, пароль). Вхід за логіном або поштою. **Відновлення пароля листом** на пошту, вказану під час реєстрації.
- **Класи та списки учнів.** Список імпортується з CSV/TXT або вставляється текстом. На кнопці класу видно, скільки учнів підключено з усіх у списку (наприклад, `2/3`), а під картками є рядок «Не підключились…».
- **Завдання** з назвою, текстом і власним кодом доступу. Кілька завдань у випадному списку зі значками стану: 📝 чернетка · 🟢 активне · ⏹ завершене. Поки одне завдання активне, перемикання на інші заблоковане.
- **Тип практичної** для кожного завдання: 🌐 веб-дизайн (HTML/CSS/JS) або 🐍 програмування (Python, див. розділ нижче).
- **Налаштування кожного завдання:**
  - шаблон із готовим стартовим кодом (за бажанням змінений вами);
  - чи можуть учні створювати файли CSS і/або JavaScript (тільки HTML, HTML+CSS, HTML+JS, усі три);
  - таймер (хвилини), продовження «＋5 хв» і дострокове завершення для всіх;
  - контроль виходів зі сторінки: облік, попередження (кнопка «на весь екран», повідомлення учню, сигнал вам після N виходів), блокування редактора до розблокування вчителем.
  - **контроль вставки коду** (академічна доброчесність): облік вставок і перетягувань готового коду з інших вкладок, сайтів чи ШІ-чатів, а також введення великого фрагмента за раз; за бажанням — заборона такої вставки. На картці учня позначка `📋N` і сповіщення вам, у вікні учня кнопка «📋 Вставки» з часом, файлом, обсягом і самим фрагментом. Не враховуються копіювання всередині власного коду учня та фрагменти з тексту завдання; можна задати мінімальний розмір фрагмента (за замовчуванням 20 символів).
- **Екрани учнів у реальному часі** (картки з мініатюрами) лише для активного завдання. Для завершеного їх можна показати чи приховати кнопкою. Клік по картці відкриває код і результат учня.
- **Чат** учня з учителем по кожній роботі, кнопка учня **«✋ Потрібна допомога»**, сповіщення про здачу робіт.
- **Перевірка:** оцінка, відгук, повернення на доопрацювання.
- **📒 Журнал оцінок** за класами та темами (за темами або таблицею учні × теми, середній бал), експорт у CSV для Excel.
- **☑ Чек-лист вимог** для веб-завдань і **🧪 автоперевірка тестами** для Python (див. розділи нижче).
- **🗄 Архів.** Роботи завершених завдань (код, статуси, оцінки, відгуки, переписка, вставки) зберігаються у файл JSON на вашому комп’ютері й видаляються з бази, щоб вона не розросталася. Завдання, зображення-зразок і журнал оцінок залишаються. Вікно «🗄 Архів» показує всі завдання з кількістю робіт у базі, дає вибрати завершені понад 30 днів тому й архівувати кілька одразу. Кнопка «📂 Переглянути файл архіву» відкриває архів (або старий файл «⬇ Роботи (JSON)»): список учнів, код кожного файлу, вигляд сторінки, вивід Python і переписка.
- **Керування завданнями:** копіювання (нове завдання з новим кодом), «Задати знову», видалення оцінених робіт, видалення завдання з попередженням зберегти результати в JSON.
- **QR-код і посилання** для швидкого входу учнів (вікно по центру екрана, зручно для проєктора).
- Експорт робіт завдання у **JSON**.

### Для учня
- Вхід за кодом завдання (або за QR-кодом чи посиланням), **вибір себе зі списку учнів класу завдання** (клас задає вчитель). Реєстрації та пароля немає.
- Редактор коду з підсвічуванням: файл `index.html`, а за дозволом вчителя файли `.css` та `.js`, які підключаються звичайними `<link>` і `<script src>`.
- Миттєвий перегляд результату й консоль із повідомленнями та помилками (з назвою файлу й номером рядка).
- Чат із учителем, кнопка «Потрібна допомога», кнопка «Здати роботу», таймер, повідомлення про оцінку та відгук.
- Роботу можна продовжити після перезавантаження чи на іншому комп’ютері.

## ☑ Чек-лист вимог для веб-завдань
У налаштуваннях веб-завдання (поки воно чернетка) є блок «☑ Чек-лист вимог». Вимоги перевіряються на готовій сторінці учня в браузері, у невидимій ізольованій рамці, тож код учня не має доступу до платформи.
- **Базові вимоги** (позначте потрібні): є `<!DOCTYPE html>`, вказано мову `lang`, є `<title>`, усі підключені файли CSS/JS існують, немає помилок JavaScript.
- **Власні вимоги:**
  - *Є елемент(и)* — селектор і скільки щонайменше (напр. `nav a`, 4);
  - *В елементів є атрибут* — напр. в усіх `img` є непорожній `alt`;
  - *Елемент містить текст* — напр. `h1` містить «Мій клас» (без урахування регістру);
  - *Стиль елемента* — властивість CSS дорівнює значенню або містить його (напр. `body` → `background-color` = `#f5f5f5`; `.card` → `display` містить `flex`). Перевіряється остаточний стиль, тому неважливо, чи учень написав `#fff`, `white` або `rgb(255,255,255)`, і де лежить CSS;
  - *Підключено файл* — напр. `style.css` існує й підключений в `index.html`;
  - *Після натискання — результат* — натиснути `#btn` (за потреби спершу ввести значення в поле `#name`) і перевірити, що `#out` містить очікуваний текст.
- Для кожної вимоги можна написати підпис для учнів («Меню з 4 пунктів»), інакше підпис складається автоматично.
- **Зразок розв’язку** (необов’язково): вставте свій `index.html` і натисніть «▶ Перевірити чек-лист на зразку», щоб переконатися, що вимоги й селектори правильні. Зразок учням не передається і зберігається лише в браузері вчителя.

Учень натискає «☑ Перевірити вимоги» і бачить, що виконано, а що ні, з поясненням («зараз: rgba(0, 0, 0, 0)», «на сторінці немає «h1»»). Під час здачі роботи перевірка запускається автоматично. На картці учня видно `☑ 5/7` (`✔` — перевірив вчитель). У вікні учня є «☑ Перевірити вимоги», а в панелі завдання — «☑ Перевірити вимоги в усіх».

> Чек-лист — орієнтир для учня й підказка для вчителя, а не автоматична оцінка: дизайн, композицію й якість коду він не оцінює. Складну логіку JavaScript (ігри, багатокрокові сценарії) перевіряє лише частково. Учень, який навмисно пише код для обману перевірки, теоретично може її обійти.


## Практичні з Python

Для завдання типу «🐍 Програмування (Python)» учень отримує редактор файлу `main.py` і консоль із `print()` та `input()` (введення значень прямо в консолі). Python працює **у браузері** (Pyodide, CPython 3.13 у WebAssembly), без сервера.

| Бібліотека | Підтримка |
|---|---|
| `math`, `random`, `json`, `csv`, `os`, `datetime` та інша стандартна бібліотека | ✅ завжди |
| `numpy`, `pandas` | ✅ вмикає вчитель у налаштуваннях завдання (pandas потребує numpy) |
| `tkinter` | 🟡 **сумісний режим** (вмикає вчитель у налаштуваннях завдання): типові шкільні програми, але не повний tkinter (див. нижче) |

- Учні можуть створювати додаткові файли `.py` (модулі для `import`), `.txt`, `.csv`, `.json`, якщо це дозволив вчитель. Їх можна читати через `open()` та `pandas.read_csv()`.
- Помилки показуються з назвою файлу та номером рядка. Нескінченні цикли зупиняються за 15 секунд, кнопка «⏹ Зупинити» перезапускає середовище.
- Учень бачить останній вивід у себе, а вчитель на картці й у вікні учня. У вікні учня є кнопка «▶ Виконати код учня»: код запускається в ізольованому середовищі, яке не має доступу до сторінки вчителя та його сесії.
- **tkinter (сумісний режим).** У Python для браузера справжнього tkinter немає, тому платформа має власну сумісну реалізацію, яку вчитель вмикає галочкою «🖼 tkinter» у завданні. Над консоллю з’являється область «вікна програми». Підтримуються: `Tk`, `Toplevel`, `Frame`, `LabelFrame`, `Label`, `Button`, `Entry`, `Text`, `Canvas` (лінія, прямокутник, овал, багатокутник, дуга, текст; `move`, `coords`, `itemconfig`, `delete`, `find_*`, `bbox`, `tag_bind`), `Checkbutton`, `Radiobutton`, `Listbox`, `Scale`, `Spinbox`, `OptionMenu`, `Scrollbar` (заглушка), `ttk` (Button, Label, Entry, Frame, Checkbutton, Radiobutton, Combobox, Scale, Progressbar, Separator), `messagebox`, `simpledialog`, змінні `StringVar`/`IntVar`/`DoubleVar`/`BooleanVar`, розміщення `pack`/`grid`/`place`, `bind` (миша, клавіші, `<<ListboxSelect>>`), `after`/`after_cancel`, `mainloop`.
  Відмінності від справжнього tkinter: `mainloop()` **не блокує** виконання (код після нього виконується одразу, а вікно живе далі); цикли `while True: ... root.update()` не підтримуються (використовуйте `after`); `messagebox`/`simpledialog` показують діалоги браузера; не підтримуються `PhotoImage`/зображення, `Menu`, `filedialog`, `colorchooser`, `Notebook`, `Treeview`. Вигляд розкладки наближений до tkinter, але не піксель у піксель. Вивід `print()` з обробників подій потрапляє в консоль, помилки показуються з номером рядка, а обробник, що виконується понад 15 секунд, зупиняється. Без увімкненого режиму `import tkinter` показує учню підказку запустити програму в Thonny/IDLE і здати код.
- **Як працює `input()`:** програма запускається повторно з уже введеними значеннями, тому вона має бути детермінованою (генератор `random` і `numpy.random` налаштовуються на однакове початкове число в межах одного запуску). Програми, які залежать від часу чи інших джерел випадковості, можуть поводитися нестабільно, якщо в них є `input()`.
- Перший запуск вантажить Python і бібліотеки (разом приблизно 18–20 МБ) з `cdn.jsdelivr.net`, далі їх бере кеш браузера. Python починає завантажуватися, щойно учень підключився, ще до запуску завдання. На шкільній мережі перевірте доступ до `cdn.jsdelivr.net`.

### 🧪 Автоперевірка тестами
У налаштуваннях Python-завдання (поки воно чернетка) є блок «🧪 Автоперевірка тестами»:
- **Тест** — це вхідні дані (кожне значення, яке читає `input()`, з нового рядка) і очікуваний вивід. Тест можна зробити **прихованим**: учень побачить лише «пройдено / не пройдено».
- Програма запускається в «тихому» режимі: у вивід потрапляє лише те, що друкує `print`. Підказки `input("Введіть число: ")` не враховуються, тож учням не треба прибирати їх із програми.
- **Як порівнювати вивід:** точний збіг (зайві пробіли в кінці рядків і порожні рядки на початку/в кінці не важать), збіг слів (пробіли й переноси не важать) або «вивід містить очікуване».
- **Час на один тест** (за замовчуванням 5 с) зупиняє нескінченні цикли. `random` у тестах завжди має однакове зерно, тож результат відтворюваний.
- **Еталонний розв’язок** (необов’язково): вставте свій розв’язок і натисніть «⤵ Заповнити очікуваний вивід з еталону» — достатньо ввести лише вхідні дані. «▶ Перевірити тести на еталоні» показує, чи тести коректні. Еталон учням не передається: він зберігається лише в браузері вчителя (у пам’яті цього браузера для цього завдання).

Учень натискає «🧪 Перевірити» й бачить результат кожного тесту: вхідні дані, очікуване й вивід своєї програми (для відкритих тестів). Під час «Здати роботу» перевірка запускається автоматично. На картці учня у вчителя з’являється позначка `🧪 2/3`; позначка `✔` означає, що результат отримав сам вчитель.

Вчитель може перевірити роботу в картці учня («🧪 Перевірити тестами», показує й приховані тести) або всі роботи одразу кнопкою «🧪 Перевірити всіх тестами» в панелі завдання. Перевірка відбувається в браузері вчителя, тож її результату можна довіряти більше, ніж результату, який надіслав учень.

> Обмеження: для програм з tkinter автоперевірка недоступна. Дані тестів (зокрема прихованих) передаються в браузер учня, тож технічно обізнаний учень може їх знайти; прихований тест — зручність, а не захист.

## Швидкий старт

### 1. Firebase
1. Створіть проєкт на <https://console.firebase.google.com>.
2. **Build → Realtime Database → Create database** (режим можна обрати будь-який, правила ви замінете на кроці 5).
3. **Build → Authentication → Sign-in method** і ввімкніть:
   - **Email/Password** (для вчителів);
   - **Anonymous** (для учнів).
4. **Project settings → General → Your apps → Web (`</>`)** і зареєструйте застосунок. Скопіюйте `firebaseConfig`.
5. **Realtime Database → Rules**: вставте вміст файлу [`firebase-rules.json`](firebase-rules.json) і натисніть **Publish**.
6. (За бажанням) **Authentication → Templates**: мова листів «Українська», назва відправника.

### 2. Налаштування `config.js`
Відкрийте `config.js` і замініть значення:

```js
const CFG={
  apiKey:"…",
  authDomain:"….firebaseapp.com",
  databaseURL:"https://…firebasedatabase.app",
  projectId:"…",
  storageBucket:"…",
  messagingSenderId:"…",
  appId:"…"
};
```

> `apiKey` у веб-конфігурації Firebase не є секретом, його видно кожному відвідувачу сторінки. Захист даних забезпечують **правила бази** з `firebase-rules.json`.

### 3. GitHub Pages
Усі файли лежать у корені репозиторію, без папок:

```
index.html          — каркас сторінки
style.css           — стилі
config.js           — ваш firebaseConfig (змінюєте лише ви)
qrcode.js           — генератор QR-кодів
core.js             — спільні функції (збирання сторінки учня, редактор, чат, зображення, вставки)
python.js           — Python у браузері та сумісний режим tkinter
student.js          — сторінка учня
teacher.js          — кабінет вчителя
main.js             — запуск
firebase-rules.json — правила бази (публікуються в консолі Firebase, на сайті не потрібні)
```

Щоб завантажити через сайт GitHub: **Add file → Upload files → choose your files**, виділіть усі файли разом (Ctrl+A у вікні вибору) і натисніть **Commit changes**.

У репозиторії: **Settings → Pages → Branch: `main`, папка `/ (root)`**. Через 1–2 хвилини сайт з’явиться за адресою:

- учні: `https://<користувач>.github.io/<репозиторій>/`
- вчитель: `https://<користувач>.github.io/<репозиторій>/#teacher`

> Адреса `github.com/…/blob/main/index.html` показує лише **код** файлу. Відкривайте сайт за адресою GitHub Pages.

## Як користуватися

### Вчитель
1. Відкрийте `…/#teacher`, зареєструйтеся (перший вхід) і підтвердьте пошту за листом.
2. Створіть **класи** («＋ Додати клас»), для кожного клас-кнопку «👥 Список класу» → вставте або імпортуйте учнів («Прізвище Ім’я» у рядку). Без списку учні класу не зможуть увійти.
3. «＋ Нове завдання»: назва, текст, налаштування. Код створюється одразу.
4. У завданні оберіть **клас, для якого воно задається** (список «🏫 Клас…»). Без вибраного класу та списку учнів завдання не запуститься.
5. За потреби додайте **зображення-зразок** (кнопка «＋ Додати зображення»): наприклад, як має виглядати результат. Воно стискається в браузері й показується учням праворуч від тексту завдання (висота не більше чверті екрана). Клік по ньому збільшує зображення в центрі; закрити можна кнопкою ✕, кліком поза зображенням або клавішею Esc. Змінювати зображення можна до запуску завдання.
6. Поділіться кодом, посиланням чи **QR-кодом** з учнями. До запуску вони бачитимуть «Очікуйте».
7. «▶ Відправити учням» запускає завдання (і таймер, якщо він увімкнений). Спостерігайте за картками, відповідайте в чаті.
8. Перевірте роботи: відкрийте учня → оцінка й відгук → «✔ Перевірено» (оцінка потрапить у журнал) або «↩ На доопрацювання».
9. «⏹ Завершити для всіх» (можна достроково). Незданні роботи здаються автоматично.
10. Збережіть результати: «⬇ Роботи (JSON)» та «📒 Журнал» → CSV.
11. Коли завдання більше не потрібне в роботі, **архівуйте його**: «📦 Архівувати роботи» (у завершеному завданні) або «🗄 Архів» у шапці кабінету, щоб вибрати кілька завдань одразу.

### Учень
1. Відкрийте сайт, введіть код (або відскануйте QR-код) і оберіть себе зі списку учнів класу, для якого вчитель задав завдання. Вибору класу немає.
2. Пишіть код у `index.html`; за потреби створюйте `style.css` / `script.js` і підключайте їх у `index.html`.
3. Натисніть «Здати роботу», коли закінчите. До завершення можна скасувати здачу.

## Безпека та приватність

Правила бази (`firebase-rules.json`) забезпечують:
- облікові записи вчителів, їхні завдання, класи й журнал змінює лише власник;
- учень (анонімний вхід) може писати тільки у власну роботу й не може змінювати оцінки, статус «Перевірено», відгуки чи журнал;
- роботи доступні власнику-учневі та вчителю; відкрити чужу роботу можна лише коли її власник не в мережі (щоб продовжити на іншому комп’ютері).

**Обмеження, про які варто знати:**
- Учень «підтверджує себе» вибором зі списку, а не паролем. Однокласник може відкрити роботу учня, який зараз не в мережі.
- Таймер, блокування після здачі, контроль виходів зі сторінки та блокування редактора діють у браузері. Технічно підготовлений учень може їх обійти. Платформа не бачить, що відбувається на іншому пристрої чи в іншій програмі.
- Контроль вставки фіксує сам факт вставки (буфер обміну, перетягування, великий фрагмент за раз), а не її джерело: відрізнити код зі ШІ від коду з іншого сайту неможливо, а код, переписаний вручну з іншого екрана чи телефона, не розпізнається. Позначка — привід поговорити з учнем, а не доказ порушення.
- Списки класів зберігаються разом із класом і читаються без пароля тим, хто має код завдання. Записуйте лише прізвище й ім’я.
- Хто знає логін вчителя, може побачити його пошту через вхід за логіном (для входу використовується відповідність логін → пошта). За потреби входьте за поштою.
- Акаунти без прив’язаної пошти (створені в ранніх версіях) не можна відновити.
- Перед використанням із неповнолітніми узгодьте його з адміністрацією закладу та за потреби ознайомте учнів і батьків з тим, що зберігається (ім’я, прізвище, код і чат по роботі).

## Ліміти й відомі особливості
- Безкоштовний тариф Firebase (Spark) дозволяє до **100 одночасних підключень** (кожна відкрита вкладка = одне). Актуальні ліміти дивіться в документації Firebase.
- Для комфортної роботи кабінету на комп’ютері вчителя краще до 30–40 карток-мініатюр одночасно.
- Мініатюри на картках показують лише розмітку та стилі (скрипти не виконуються). Кнопка «▶ Виконати JS» у вікні учня запускає скрипти.
- **Трафік бази.** Код учнів зберігається окремо від статусів, тому кабінет не отримує файли всіх учнів при кожному збереженні. Мініатюри оновлюються за розкладом (над картками: кожні 10 с / 30 с / щохвилини / лише вручну, за замовчуванням 30 с). Відкритий учень оновлюється наживо. Учень зберігає код після 2 с паузи (або щонайменше раз на 10 с безперервного набору та при перемиканні вкладки). Зображення-зразок стискається до ~250 КБ, бо його завантажує кожен учень.
- Учні не можуть створювати папки та файли, відмінні від `.css` і `.js`. Додаткові `.html`-сторінки не підтримуються.
- Таймер використовує серверний час Firebase, тож годинники комп’ютерів не впливають.

## Оновлення
1. Завантажте в репозиторій нові файли (**Add file → Upload files**). Файл **`config.js` не замінюйте**: у ньому ваш `firebaseConfig`.
   - Посилання на скрипти в `index.html` мають мітку версії (`?v=…`), тому після оновлення браузери учнів беруть нові файли, а не старі з кешу. Якщо оновлюєте лише один `.js`-файл без нового `index.html`, учням варто оновити сторінку з Ctrl+F5.
   - Перехід з однофайлової версії: замініть старий `index.html` новим і додайте решту файлів; свій `firebaseConfig` перенесіть зі старого файлу в `config.js`.
2. Якщо змінився `firebase-rules.json`, опублікуйте правила заново: **Realtime Database → Rules → Publish**. Робіть це поза уроком: старі сторінки з новими правилами, і навпаки, можуть працювати неповністю.

## Структура даних у Firebase

| Вузол | Призначення |
|---|---|
| `teachers/{uid}` | профіль вчителя |
| `logins/{логін}` | відповідність логіну пошті (для входу та відновлення пароля) |
| `classes/{uid}/{клас}` | назва класу та список учнів `roster` |
| `tasks/{uid}/{завдання}` | назва, текст, стан, позначка архіву (`arch`), клас (`cls`, `cn`), код, тип (`ttype`: `web`/`py`), налаштування, таймер |
| `timg/{uid}/{завдання}` | зображення-зразок завдання (стиснений JPEG у вигляді data-URL) |
| `works/…/{учень}/ws` | результат чек-листа вимог: виконано `p` з `n`, коли (`at`), чи перевірив вчитель (`t`) |
| `works/…/{учень}/ts` | результат автоперевірки: пройдено `p` з `n`, коли (`at`), чи перевірив вчитель (`t`) |
| `works/…/{учень}/pc`, `pz`, `pl` | кількість і обсяг вставок коду, останні 100 вставлених фрагментів |
| `codes/{код}` | пошук завдання за кодом |
| `owners/{завдання}` | власник завдання (для правил) |
| `works/{завдання}/{учень}` | робота учня без коду: статус, оцінка, відгук, чат, лічильники, позначки, останній вивід Python |
| `code/{завдання}/{учень}` | файли учня (код). Вчитель читає їх разово для мініатюр і наживо лише для відкритого учня |
| `journal/{uid}/{клас}/{завдання}/{учень}` | журнал оцінок (окремо від робіт) |

## Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| На екрані лише код | відкрито `github.com/…/blob/…` замість адреси GitHub Pages |
| Порожня сторінка | вставлено `firebaseConfig` у `config.js`; усі файли `.js` і `style.css` лежать поруч з `index.html`; F12 → Console (червоні повідомлення) |
| «Вхід для учнів не налаштовано» | у Firebase не ввімкнено **Anonymous** |
| «У Firebase не ввімкнено вхід за email/паролем» | ввімкніть **Email/Password** |
| `PERMISSION_DENIED` у консолі | опубліковано правила з `firebase-rules.json` і оновлено `index.html` |
| Оцінка не потрапляє в журнал | оновлено правила (розділ `journal`) |
| Не приходить лист для відновлення | папка «Спам»; пошта вказана при реєстрації та підтверджена |
| Учні не можуть увійти до класу | для класу не створено **список учнів** |
| Python не запускається («не вдалося завантажити з cdn.jsdelivr.net») | немає доступу до `cdn.jsdelivr.net` із шкільної мережі; перевірте інтернет і фільтри |
