# Клас-код — платформа для практичних із програмування та веб-дизайну

Онлайн-платформа для спільної одночасної роботи класу над практичними завданнями з веб-дизайну (HTML, CSS, JavaScript) та програмування (Python). Учні пишуть код у браузері й одразу бачать результат, а вчитель у реальному часі бачить екрани всіх учнів, спілкується з ними в чаті, перевіряє роботи й веде журнал оцінок.

Це **один файл `index.html`**, який працює на безкоштовному GitHub Pages. Окремого сервера немає: дані зберігає Firebase (Realtime Database + Authentication).

> Інтерфейс українською мовою.

---

## Можливості

### Для вчителя
- **Реєстрація та вхід** (ім’я, по батькові, прізвище, пошта, логін, пароль). Вхід за логіном або поштою. **Відновлення пароля листом** на пошту, вказану під час реєстрації.
- **Класи та списки учнів.** Список імпортується з CSV/TXT або вставляється текстом. На кнопці класу видно, скільки учнів підключено з усіх у списку (наприклад, `2/3`), а під картками є рядок «Не підключились…».
- **Завдання** з назвою, текстом і власним кодом доступу. Кілька завдань у випадному списку зі значками стану: 📝 чернетка · 🟢 активне · ⏹ завершене. Поки одне завдання активне, перемикання на інші заблоковане.
- **Тип практичної** для кожного завдання: 🌐 веб-дизайн (HTML/CSS/JS) або 🐍 програмування (Python, див. розділ нижче).
- **Налаштування кожного завдання:**
  - шаблон із готовим стартовим кодом (за бажанням змінений вами);
  - чи можуть учні створювати файли CSS і/або JavaScript (тільки HTML, HTML+CSS, HTML+JS, усі три);
  - таймер (хвилини), продовження «＋5 хв» і дострокове завершення для всіх;
  - контроль виходів зі сторінки: облік, попередження (кнопка «на весь екран», повідомлення учню, сигнал вам після N виходів), блокування редактора до розблокування вчителем.
- **Екрани учнів у реальному часі** (картки з мініатюрами) лише для активного завдання. Для завершеного їх можна показати чи приховати кнопкою. Клік по картці відкриває код і результат учня.
- **Чат** учня з учителем по кожній роботі, кнопка учня **«✋ Потрібна допомога»**, сповіщення про здачу робіт.
- **Перевірка:** оцінка, відгук, повернення на доопрацювання.
- **📒 Журнал оцінок** за класами та темами (за темами або таблицею учні × теми, середній бал), експорт у CSV для Excel.
- **Керування завданнями:** копіювання (нове завдання з новим кодом), «Задати знову», видалення оцінених робіт, видалення завдання з попередженням зберегти результати в JSON.
- **QR-код і посилання** для швидкого входу учнів (вікно по центру екрана, зручно для проєктора).
- Експорт робіт завдання у **JSON**.

### Для учня
- Вхід за кодом завдання (або за QR-кодом чи посиланням), вибір класу й **вибір себе зі списку класу**. Реєстрації та пароля немає.
- Редактор коду з підсвічуванням: файл `index.html`, а за дозволом вчителя файли `.css` та `.js`, які підключаються звичайними `<link>` і `<script src>`.
- Миттєвий перегляд результату й консоль із повідомленнями та помилками (з назвою файлу й номером рядка).
- Чат із учителем, кнопка «Потрібна допомога», кнопка «Здати роботу», таймер, повідомлення про оцінку та відгук.
- Роботу можна продовжити після перезавантаження чи на іншому комп’ютері.

## Практичні з Python

Для завдання типу «🐍 Програмування (Python)» учень отримує редактор файлу `main.py` і консоль із `print()` та `input()` (введення значень прямо в консолі). Python працює **у браузері** (Pyodide, CPython 3.13 у WebAssembly), без сервера.

| Бібліотека | Підтримка |
|---|---|
| `math`, `random`, `json`, `csv`, `os`, `datetime` та інша стандартна бібліотека | ✅ завжди |
| `numpy`, `pandas` | ✅ вмикає вчитель у налаштуваннях завдання (pandas потребує numpy) |
| `tkinter` | ❌ у браузері недоступний (див. нижче) |

- Учні можуть створювати додаткові файли `.py` (модулі для `import`), `.txt`, `.csv`, `.json`, якщо це дозволив вчитель. Їх можна читати через `open()` та `pandas.read_csv()`.
- Помилки показуються з назвою файлу та номером рядка. Нескінченні цикли зупиняються за 15 секунд, кнопка «⏹ Зупинити» перезапускає середовище.
- Учень бачить останній вивід у себе, а вчитель на картці й у вікні учня. У вікні учня є кнопка «▶ Виконати код учня»: код запускається в ізольованому середовищі, яке не має доступу до сторінки вчителя та його сесії.
- **tkinter:** модуля tkinter немає в Python для браузера. Завдання з tkinter учні виконують у Thonny/IDLE на своєму комп’ютері, а тут здають код для перегляду й оцінювання. Спроба `import tkinter` показує учню підказку про це. Сумісний із tkinter шар (вікна, кнопки, Canvas) можна додати пізніше.
- **Як працює `input()`:** програма запускається повторно з уже введеними значеннями, тому вона має бути детермінованою (генератор `random` і `numpy.random` налаштовуються на однакове початкове число в межах одного запуску). Програми, які залежать від часу чи інших джерел випадковості, можуть поводитися нестабільно, якщо в них є `input()`.
- Перший запуск вантажить Python і бібліотеки (разом приблизно 18–20 МБ) з `cdn.jsdelivr.net`, далі їх бере кеш браузера. Python починає завантажуватися, щойно учень підключився, ще до запуску завдання. На шкільній мережі перевірте доступ до `cdn.jsdelivr.net`.

## Швидкий старт

### 1. Firebase
1. Створіть проєкт на <https://console.firebase.google.com>.
2. **Build → Realtime Database → Create database** (режим можна обрати будь-який, правила ви замінете на кроці 5).
3. **Build → Authentication → Sign-in method** і ввімкніть:
   - **Email/Password** (для вчителів);
   - **Anonymous** (для учнів).
4. **Project settings → General → Your apps → Web (`</>`)** і зареєструйте застосунок. Скопіюйте `firebaseConfig`.
5. **Realtime Database → Rules**: вставте вміст файлу [`firebase-rules.json`](firebase-rules.json) і натисніть **Publish**.
6. (За бажанням) **Authentication → Templates**: мова листів «Українська», назва відправника.

### 2. Налаштування `index.html`
Відкрийте `index.html` і замініть значення у верхньому блоці:

```js
const CFG={
  apiKey:"…",
  authDomain:"….firebaseapp.com",
  databaseURL:"https://…firebasedatabase.app",
  projectId:"…",
  storageBucket:"…",
  messagingSenderId:"…",
  appId:"…"
};
```

> `apiKey` у веб-конфігурації Firebase не є секретом, його видно кожному відвідувачу сторінки. Захист даних забезпечують **правила бази** з `firebase-rules.json`.

### 3. GitHub Pages
У репозиторії: **Settings → Pages → Branch: `main`, папка `/ (root)`**. Через 1–2 хвилини сайт з’явиться за адресою:

- учні: `https://<користувач>.github.io/<репозиторій>/`
- вчитель: `https://<користувач>.github.io/<репозиторій>/#teacher`

> Адреса `github.com/…/blob/main/index.html` показує лише **код** файлу. Відкривайте сайт за адресою GitHub Pages.

## Як користуватися

### Вчитель
1. Відкрийте `…/#teacher`, зареєструйтеся (перший вхід) і підтвердьте пошту за листом.
2. Створіть **класи** («＋ Додати клас»), для кожного клас-кнопку «👥 Список класу» → вставте або імпортуйте учнів («Прізвище Ім’я» у рядку). Без списку учні класу не зможуть увійти.
3. «＋ Нове завдання»: назва, текст, налаштування. Код створюється одразу.
4. Поділіться кодом, посиланням чи **QR-кодом** з учнями. До запуску вони бачитимуть «Очікуйте».
5. «▶ Відправити учням» запускає завдання (і таймер, якщо він увімкнений). Спостерігайте за картками, відповідайте в чаті.
6. Перевірте роботи: відкрийте учня → оцінка й відгук → «✔ Перевірено» (оцінка потрапить у журнал) або «↩ На доопрацювання».
7. «⏹ Завершити для всіх» (можна достроково). Незданні роботи здаються автоматично.
8. Збережіть результати: «⬇ Роботи (JSON)» та «📒 Журнал» → CSV.

### Учень
1. Відкрийте сайт, введіть код (або відскануйте QR-код), оберіть клас і себе зі списку.
2. Пишіть код у `index.html`; за потреби створюйте `style.css` / `script.js` і підключайте їх у `index.html`.
3. Натисніть «Здати роботу», коли закінчите. До завершення можна скасувати здачу.

## Безпека та приватність

Правила бази (`firebase-rules.json`) забезпечують:
- облікові записи вчителів, їхні завдання, класи й журнал змінює лише власник;
- учень (анонімний вхід) може писати тільки у власну роботу й не може змінювати оцінки, статус «Перевірено», відгуки чи журнал;
- роботи доступні власнику-учневі та вчителю; відкрити чужу роботу можна лише коли її власник не в мережі (щоб продовжити на іншому комп’ютері).

**Обмеження, про які варто знати:**
- Учень «підтверджує себе» вибором зі списку, а не паролем. Однокласник може відкрити роботу учня, який зараз не в мережі.
- Таймер, блокування після здачі, контроль виходів зі сторінки та блокування редактора діють у браузері. Технічно підготовлений учень може їх обійти. Платформа не бачить, що відбувається на іншому пристрої чи в іншій програмі.
- Списки класів зберігаються разом із класом і читаються без пароля тим, хто має код завдання. Записуйте лише прізвище й ім’я.
- Хто знає логін вчителя, може побачити його пошту через вхід за логіном (для входу використовується відповідність логін → пошта). За потреби входьте за поштою.
- Акаунти без прив’язаної пошти (створені в ранніх версіях) не можна відновити.
- Перед використанням із неповнолітніми узгодьте його з адміністрацією закладу та за потреби ознайомте учнів і батьків з тим, що зберігається (ім’я, прізвище, код і чат по роботі).

## Ліміти й відомі особливості
- Безкоштовний тариф Firebase (Spark) дозволяє до **100 одночасних підключень** (кожна відкрита вкладка = одне). Актуальні ліміти дивіться в документації Firebase.
- Для комфортної роботи кабінету на комп’ютері вчителя краще до 30–40 карток-мініатюр одночасно.
- Мініатюри на картках показують лише розмітку та стилі (скрипти не виконуються). Кнопка «▶ Виконати JS» у вікні учня запускає скрипти.
- Учні не можуть створювати папки та файли, відмінні від `.css` і `.js`. Додаткові `.html`-сторінки не підтримуються.
- Таймер використовує серверний час Firebase, тож годинники комп’ютерів не впливають.

## Оновлення
1. Замініть `index.html` у репозиторії новою версією (збережіть свій блок `CFG`).
2. Якщо змінився `firebase-rules.json`, опублікуйте правила заново: **Realtime Database → Rules → Publish**. Робіть це поза уроком: старі сторінки з новими правилами, і навпаки, можуть працювати неповністю.

## Структура даних у Firebase

| Вузол | Призначення |
|---|---|
| `teachers/{uid}` | профіль вчителя |
| `logins/{логін}` | відповідність логіну пошті (для входу та відновлення пароля) |
| `classes/{uid}/{клас}` | назва класу та список учнів `roster` |
| `tasks/{uid}/{завдання}` | назва, текст, стан, код, тип (`ttype`: `web`/`py`), налаштування, таймер |
| `codes/{код}` | пошук завдання за кодом |
| `owners/{завдання}` | власник завдання (для правил) |
| `works/{завдання}/{учень}` | робота учня: файли, статус, оцінка, чат, лічильники, останній вивід Python (`out`) |
| `journal/{uid}/{клас}/{завдання}/{учень}` | журнал оцінок (окремо від робіт) |

## Якщо щось не працює

| Симптом | Що перевірити |
|---|---|
| На екрані лише код | відкрито `github.com/…/blob/…` замість адреси GitHub Pages |
| Порожня сторінка | вставлено `firebaseConfig` у `CFG`; F12 → Console (червоні повідомлення) |
| «Вхід для учнів не налаштовано» | у Firebase не ввімкнено **Anonymous** |
| «У Firebase не ввімкнено вхід за email/паролем» | ввімкніть **Email/Password** |
| `PERMISSION_DENIED` у консолі | опубліковано правила з `firebase-rules.json` і оновлено `index.html` |
| Оцінка не потрапляє в журнал | оновлено правила (розділ `journal`) |
| Не приходить лист для відновлення | папка «Спам»; пошта вказана при реєстрації та підтверджена |
| Учні не можуть увійти до класу | для класу не створено **список учнів** |
| Python не запускається («не вдалося завантажити з cdn.jsdelivr.net») | немає доступу до `cdn.jsdelivr.net` із шкільної мережі; перевірте інтернет і фільтри |
